# Build and offline installation

Tested source: AIRON initial lifecycle `16c6bd745edacaa4ad7b435cc52de935e1d1802f`; final qualification target `0f4cd7e20f4c19577b5a73b9d1dacdc221f3085a`; native interface `f1ba9fc2072dac1431543fd4961baaa2762b8ea9`. See `BENCHMARKS.json` and `evidence/local/PROVENANCE.json` for per-run revisions. Local hardware: Linux 6.18.57, AMD EPYC 9V74, 9 visible CPUs, 10,206,472 KiB RAM, no GPU; inference comparisons restricted to CPUs 0–1. Hosted hardware: Ubuntu 22.04, Linux 6.8 Azure, 4 visible CPUs, 16,371,436 KiB RAM; the corrected two-CPU run enforced an 8 GiB cgroup limit but training timed out; separate four-CPU training and two-CPU serving qualification is in progress. No claim of independent administration.

1. Use Linux x86_64 with Python 3.12, a C/C++ toolchain, CMake, Rust 1.99.1, `git`, `bubblewrap`, `util-linux` (`unshare`, `prlimit`), and `strace`. Provisioning is an explicitly online administrative phase. Serving must never install packages or download a model.
2. Check out this AIRON qualification revision and separately check out AIP `f1ba9fc2072dac1431543fd4961baaa2762b8ea9` with permission to use its proprietary component. Build `cargo +1.99.1 build --locked -p syntriass-runtime --bins` in that original repository. Do not copy its source or change its notices.
3. Follow `.github/workflows/p0-056.yml` for exact acquisition, Python dependency installation, model provisioning and llama.cpp build commands. The inference source pin is `2a4daf0e08d6a9b6993ee0d4a9a3cfc35a6f405c`. Use `llama-completion`; the interactive CLI is not this backend. Curl support is disabled.
4. Provision SmolLM2-135M-Instruct revision `12fd25f77366fa6b3b4b768ec3050bf629380bac` using the preserved P0-052 model lock. Conversion to F16 GGUF uses the pinned llama.cpp converter. Record the converted artifact hash; it is not automatically trusted by filename.
5. Build the offline wheelhouse with `services/unified-runtime/scripts/prepare_offline.py --output /absolute/wheelhouse`. The serving environment contains the qualified adaptation package; unified-runtime is built from local source. Preserve `requirements.lock`, `wheelhouse.json`, licence notices and all wheels together.
6. Create a new virtual environment, explicitly unset `PYTHONPATH`, and run pip with `--no-index --find-links /absolute/wheelhouse --require-hashes -r /absolute/wheelhouse/requirements.lock`. Run `pip check`. Install and test inside an external-network-free namespace. Never omit hashes to work around a missing package.
7. Provision a new workspace using `services/unified-runtime/scripts/provision.py`, passing `--assets`, `--aip-dir`, `--bin-dir`, `--llama`, `--gguf` and `--approve-synthetic-data`. This explicit flag is only for the provided fictional fixture. It does not authorize customer data training.
8. Run `run_demo.py --root /absolute/state --report /absolute/demo.json --backend llama --approve-synthetic-test-deployment`. Run `installed_smoke.py` from the newly installed environment with `PYTHONPATH` unset. Successful compilation or a static page is not acceptance.
9. Launch `python -m airon_runtime.server --root /absolute/state`. Open `http://127.0.0.1:8767` locally and use the terminal-issued token for the desired role. Tokens are not persisted or placed in URLs. Grant expiry is 24 hours for the synthetic fixture; re-provision for a fresh demonstration instead of editing the grant silently.

The optional two-part offline distribution has a top-level `install_offline.sh`. Extract both archives into the same directory, set `AIRON_NATIVE_SOURCE`, `AIRON_NATIVE_BIN`, and a new absolute `AIRON_WORKSPACE`, then execute it. The native AIP binaries remain separately provisioned due to the unresolved distribution boundary. System prerequisites are not bundled. The archive is a platform-specific provisioning aid, not a universally portable OS image.

Pinned source/build recipes and hash-verified binaries are provided. Bit-identical native rebuilds across independent toolchains have not been demonstrated. No guarantee of cross-distribution ABI compatibility is made.
